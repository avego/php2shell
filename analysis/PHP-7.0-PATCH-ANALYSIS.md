## 1. Специфика архитектуры PHP 7.0 (Первое поколение Zend Engine 3)

PHP 7.0.0 стал революционным релизом PHP, в котором архитектура была полностью переписана:
1. **Новый аллокатор Zend MM (Compact Arena Allocator):** В PHP 7.0 впервые появился компактный бинарный аллокатор со слотами (bins 0..29) и страницами памяти (`zend_mm_page`), заменивший старый аллокатор PHP 5.6. Однако в нём сохранялся жесткий аварийный прыжок `longjmp` при исчерпании лимита `memory_limit`.
2. **Переход на zval нового формата:** В 7.0 `zval` уменьшился с 24 байт до 16 байт и перестал аллоцироваться в куче.
3. **Объем изменений бэкпорта:** Поскольку PHP 7.0 не имел развитой системы внутренних интерфейсов Soft-OOM, появившихся в 7.4/8.0, данный патч является самым объемным в семействе 7.x — **11 784 строки кода** в 76 файлах ядра и расширений.

## 3. Детальный аудит ключевых компонентов защиты

### 3.1. Устранение Use-After-Free в `Zend/zend_llist.c`

В оригинальном `php-7.0.33`:
```c
// До патча:
ZEND_API void zend_llist_destroy(zend_llist *l)
{
    zend_llist_element *current=l->head, *next;
    while (current) {
        next = current->next;
        if (l->dtor) l->dtor(current->data);
        pefree(current, l->persistent);
        current = next;
    }
    l->count = 0; // l->head и l->tail оставались висячими указателями!
}
```

Патч вносит исправление:
```diff
--- a/Zend/zend_llist.c
+++ b/Zend/zend_llist.c
@@ -112,6 +112,8 @@
 		current = next;
 	}
 
+	l->head  = NULL;
+	l->tail  = NULL;
 	l->count = 0;
 }
```
**Эффект безопасности:** Полная блокировка Use-After-Free и Double Free при завершении запроса.

### 3.2. Архитектура Soft-OOM (`Zend/zend_alloc.c` и `zend_alloc.h`)

* В ядро аллокатора интегрирован полноценный отложенный отказ `EG(delayed_oom)`.
* Введена директива `memory_hard_limit_percent` (по умолчанию 125%).
* При исчерпании `memory_limit` (Soft Limit) память аллоцируется из 25%-й резервной подушки безопасности, взводится флаг `ZEND_OOM_STATE_PENDING` и прерывание виртуальной машины `EG(vm_interrupt)`.
* При жестком исчерпании 125% вызывается прямой системный вызов ядра ОС `_exit(1)`, исключая выполнение любого кода деструкторов.

---

### 3.3. Защита сетевого парсера RFC 1867 (`main/rfc1867.c`)

1. **Фильтрация MIME-заголовков (`php_mime_should_save_hdr`):**
   Парсер сохраняет только `Content-Disposition` и `Content-Type`. Все нестандартные заголовки отбрасываются до аллокации памяти.
2. **Контроль `post_max_size` в буфере:**
   Функция `fill_buffer` отсекает входящий поток данных при `SG(read_post_bytes) > SG(post_max_size)`.
3. **Безопасная точка выхода по Soft-OOM (`goto oom`):**
   При фиксации нехватки памяти парсер освобождает буфер и ключ, после чего штатно возвращает `0`.
4. **Обнуление указателя хэш-таблицы файлов:**
   ```c
   FREE_HASHTABLE(SG(rfc1867_uploaded_files));
   SG(rfc1867_uploaded_files) = NULL;
   ```
