1. **Zend Memory Manager v2.2:**
   * В PHP 5.2 аллокатор Zend MM использует классическую модель деления блоков кучи на сегменты с кэшированием корзин свободных блоков (`free_buckets`).

## 3. Детальный аудит ключевых компонентов защиты

### 3.1. Устранение Use-After-Free в связанных списках (`Zend/zend_llist.c`)

В оригинальном `php-5.2.17`:
```c
// До патча:
ZEND_API void zend_llist_destroy(zend_llist *l)
{
    zend_llist_element *current=l->head, *next;
    while (current) {
        next = current->next;
        if (l->dtor) l->dtor(current->data);
        pefree(current, l->persistent);
        current = next;
    }
    l->count = 0; // l->head и l->tail оставались висячими указателями!
}
```

Патч вносит исправление:
```diff
--- a/Zend/zend_llist.c
+++ b/Zend/zend_llist.c
@@ -109,6 +109,8 @@
 		current = next;
 	}
 
+	l->head  = NULL;
+	l->tail  = NULL;
 	l->count = 0;
 }
```
**Эффект безопасности:** Принудительное обнуление `head` и `tail` исключает возможность обращения к освобожденным узлам связанного списка или выполнения повторной очистки (`double-free`) при вызове деструкторов.

### 3.2. Архитектура Soft-OOM и Hard Limit (`Zend/zend_alloc.c` и `zend_alloc.h`)

1. **Динамический расчет Hard Limit (`zend_mm_update_hard_limit`):**
   ```c
   size_t headroom = MIN(heap->limit, (size_t) 1024 * 1024 * 1024);
   size_t hard_limit = (heap->limit > (size_t) -1 - headroom) ? (size_t) -1 : heap->limit + headroom;
   heap->hard_limit = hard_limit;
   ```
   Выделяется динамический буфер (headroom) сверх мягкого `memory_limit` (до +100% объема, но не более 1 ГБ).
2. **Мягкое состояние ошибки OOM (`EG(delayed_oom)`):**
   * При исчерпании `limit` выставляется статус:  
     `EG(delayed_oom) = ZEND_OOM_STATE_PENDING;`
   * Аллокатор **не прерывает** поток выполнения, позволяя парсеру POST-данных штатно свернуть структуры данных.
3. **Безопасная точка аварийной паники (`_exit(137)`):**
   * Если приложение пытается потребить больше жесткого предела (`heap->hard_limit`), срабатывает функция `zend_mm_hard_limit_error`:
     ```c
     fprintf(stderr, "Hard memory limit of %lu bytes exhausted (tried to allocate %lu bytes)...\n", ...);
     _exit(137);
     ```
   * Код завершения `137` (SIGKILL) мгновенно убивает процесс ОС без вызова деструкторов PHP, полностью исключая манипуляцию памятью через OOM.

### 3.3. Защита сетевого парсера RFC 1867 (`main/rfc1867.c`)

1. **Строгая фильтрация MIME-заголовков:**
   ```c
   static zend_bool php_mime_should_save_hdr(const char *name)
   {
       return !strcasecmp(name, "Content-Disposition")
           || !strcasecmp(name, "Content-Type");
   }
   ```
   Все сторонние заголовки парсер отбрасывает до аллокации памяти.
2. **Отсечение по `post_max_size` в буфере:**
   ```c
   if (SG(post_max_size) > 0 && SG(read_post_bytes) > SG(post_max_size)) {
       return 0;
   }
   ```
   Блокирует переполнение буфера входящими сетевыми пакетами.
3. **Безопасный выход по `goto oom`:**
   В случае нехватки памяти парсер корректно освобождает строковые буферы и возвращает `0`.
