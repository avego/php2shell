## 1. Специфика ветки PHP 7.2

PHP 7.2 знаменует зрелую эпоху архитектуры **Zend Engine 3.2**:
* В этой версии был внедрен современный интерфейс криптографии (Sodium) и улучшена система типов параметров/возвратов.
* Как и в более поздних версиях линейки 7.x, при возникновении ошибки нехватки памяти аллокатор Zend MM совершал жесткий прыжок `longjmp` (`zend_bailout`), бросая ядро в фазу завершения запроса (`php_request_shutdown`) с повреждёнными внутренними структурами.
* Исходный код `php-7.2.34` содержал неполную реализацию `zend_llist_destroy`, оставлявшую указатели `head` и `tail` в подвешенном состоянии после вызова деструкторов узлов.

## 3. Детальный аудит ключевых компонентов защиты

### 3.1. Устранение Use-After-Free в `Zend/zend_llist.c`

В оригинальном `php-7.2.34`:
```c
// До патча:
ZEND_API void zend_llist_destroy(zend_llist *l)
{
    zend_llist_element *current=l->head, *next;
    while (current) {
        next = current->next;
        if (l->dtor) l->dtor(current->data);
        pefree(current, l->persistent);
        current = next;
    }
    l->count = 0; // l->head и l->tail оставались старыми адресами памяти!
}
```

Патч явно добавляет обнуление указателей:
```diff
--- a/Zend/zend_llist.c
+++ b/Zend/zend_llist.c
@@ -112,6 +112,8 @@
 		current = next;
 	}
 
+	l->head  = NULL;
+	l->tail  = NULL;
 	l->count = 0;
 }
```
**Эффект безопасности:** Принудительное обнуление `l->head` и `l->tail` делает невозможным выполнение повторной очистки по освобожденным адресам памяти при фатальном выходе из запроса.

### 3.2. Внедрение архитектуры Soft-OOM (`Zend/zend_alloc.c` и `zend_alloc.h`)

* В ядро аллокатора интегрирован механизм мягкого OOM `EG(delayed_oom)`.
* Введена директива `memory_hard_limit_percent` (по умолчанию 125%).
* При достижении лимита `memory_limit` (Soft Limit) память аллоцируется из 25%-й резервной зоны, взводится прерывание виртуальной машины `EG(vm_interrupt)` и флаг `ZEND_OOM_STATE_PENDING`.
* Если объем запроса превышает 125% жесткого лимита (Hard Limit), вызывается `_exit(1)` — процесс завершается немедленно без выполнения фазы `php_request_shutdown` и деструкторов объектов.

---

### 3.3. Защита сетевого парсера RFC 1867 (`main/rfc1867.c`)

1. **Фильтрация MIME-заголовков (`php_mime_should_save_hdr`):**
   Парсер отбрасывает все заголовки, кроме `Content-Disposition` и `Content-Type`. Атакующий не может использовать посторонние MIME-заголовки для неконтролируемого исчерпания памяти.
2. **Контроль `post_max_size` в буфере:**
   Функция `fill_buffer` немедленно прекращает чтение при `SG(read_post_bytes) > SG(post_max_size)`.
3. **Безопасная точка выхода по Soft-OOM (`goto oom`):**
   При фиксации нехватки памяти парсер освобождает буфер и ключ, после чего штатно возвращает `0`.
4. **Обнуление указателя хэш-таблицы файлов:**
   ```c
   FREE_HASHTABLE(SG(rfc1867_uploaded_files));
   SG(rfc1867_uploaded_files) = NULL;
   ```
