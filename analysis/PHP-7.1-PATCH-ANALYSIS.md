## 1. Специфика ветки PHP 7.1

PHP 7.1 — это поколение раннего **Zend Engine 3.1**:
* В этой версии появились nullable-типы, поддержка отрицательных строковых смещений и симметричная деструктуризация массивов.
* Однако в архитектуре аллокатора Zend MM сохранялась унаследованная модель немедленного аварийного прыжка (`longjmp`), которая приводила к повреждению структур парсера и последующему Use-After-Free при вызове деструкторов завершения запроса (`php_request_shutdown`).
* В исходном коде `php-7.1.33` функция `zend_llist_destroy` содержала известную уязвимость с отсутствием обнуления указателей `head` и `tail`.

## 3. Детальный аудит компонентов защиты

### 3.1. Устранение Use-After-Free в `Zend/zend_llist.c`

```diff
--- a/Zend/zend_llist.c
+++ b/Zend/zend_llist.c
@@ -112,6 +112,8 @@
 		current = next;
 	}
 
+	l->head  = NULL;
+	l->tail  = NULL;
 	l->count = 0;
 }
```
**Эффект безопасности:** Явное обнуление `head` и `tail` гарантирует безопасность повторных вызовов деструкторов списков при фатальном выходе из запроса.

---

### 3.2. Архитектура Soft-OOM (`Zend/zend_alloc.c` и `zend_alloc.h`)

* В ядро аллокатора интегрирован двухфазный механизм Soft/Hard OOM (`EG(delayed_oom)`).
* Введена директива `memory_hard_limit_percent` (по умолчанию 125%).
* При исчерпании `memory_limit` (Soft Limit) память аллоцируется из 25%-й резервной подушки безопасности, взводится флаг `ZEND_OOM_STATE_PENDING` и прерывание виртуальной машины `EG(vm_interrupt)`.
* При жестком исчерпании 125% вызывается прямой системный вызов ядра ОС `_exit(1)`, исключая выполнение любого пользовательского или служебного кода деструкторов.

---

### 3.3. Защита сетевого парсера RFC 1867 (`main/rfc1867.c`)

1. **Фильтрация MIME-заголовков (`php_mime_should_save_hdr`):**
   Парсер сохраняет только `Content-Disposition` и `Content-Type`. Все нестандартные заголовки отбрасываются до аллокации памяти.
2. **Контроль `post_max_size` в буфере:**
   Функция `fill_buffer` отсекает входящий поток данных при `SG(read_post_bytes) > SG(post_max_size)`.
3. **Безопасная точка выхода по Soft-OOM (`goto oom`):**
   При фиксации нехватки памяти парсер освобождает буфер и ключ, после чего штатно возвращает `0`.
4. **Обнуление указателя хэш-таблицы файлов:**
   ```c
   FREE_HASHTABLE(SG(rfc1867_uploaded_files));
   SG(rfc1867_uploaded_files) = NULL;
   ```

### 3.4. Адаптация стандартных библиотек
Модифицированы 85 файлов, обеспечивая безопасную работу со строками и структурами данных при нехватке памяти:
