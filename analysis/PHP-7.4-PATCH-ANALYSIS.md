## 1. Значение ветки PHP 7.4 и специфика Debian 11 Bullseye

PHP 7.4.33 — это вершина поколения **Zend Engine 3**:
* Это самая популярная версия PHP для унаследованных (legacy) корпоративных проектов, интернет-магазинов и CMS.
* В **Debian 11 (Bullseye)** именно PHP 7.4 является **штатной системной версией**, поставляемой из репозиториев ОС и управляемой системным демоном `php7.4-fpm.service`.
* В дистрибутиве Debian сборка пакетов (`dpkg-buildpackage`) предъявляет строгие требования к сборочному окружению: если патч затрагивает файлы лексических сканеров (`.re`) или грамматик (`.y`), система может потребовать строго фиксированные версии генераторов `re2c` и `bison`. Именно поэтому для Debian 11 подготовлен расширенный вариант патча с предкомпилированными C-файлами.

## 4. Детальный аудит механизмов защиты в PHP 7.4.33

### 4.1. Закрытие Use-After-Free в связанных списках (`Zend/zend_llist.c`)

В оригинальном `php-7.4.33` функция `zend_llist_destroy` содержала критический дефект очистки:
```c
// До патча:
ZEND_API void zend_llist_destroy(zend_llist *l)
{
    zend_llist_element *current=l->head, *next;
    while (current) {
        next = current->next;
        if (l->dtor) l->dtor(current->data);
        pefree(current, l->persistent);
        current = next;
    }
    l->count = 0; // l->head и l->tail оставались висячими указателями!
}
```

Патч вносит исправление:
```diff
--- a/Zend/zend_llist.c
+++ b/Zend/zend_llist.c
@@ -112,6 +112,8 @@
 		current = next;
 	}
 
+	l->head  = NULL;
+	l->tail  = NULL;
 	l->count = 0;
 }
```
Это увеличивает размер скомпилированной функции с `0x57` (87 байт) до `0x67` (103 байта), делая повторное уничтожение списка абсолютно безопасным.

---

### 4.2. Архитектура Soft-OOM в Zend Engine 3 (`Zend/zend_alloc.c`)

В аллокатор Zend Engine 3 интегрирован полноценный двухфазный механизм:
1. **Подушка безопасности (Headroom 25%):**
   * При достижении значения `memory_limit` аллокатор не завершает работу аварийно.
   * Выставляется флаг `EG(delayed_oom).state = ZEND_OOM_STATE_PENDING`.
   * Память выделяется из резервной области в пределах `memory_hard_limit_percent` (по умолчанию 125%).
2. **Безопасная точка выхода:**
   * В виртуальной машине Zend VM 3 проверка отложенного OOM интегрирована в диспетчер опкодов (`ZEND_VM_INTERRUPT`).
   * В SAPI выгрузка происходит строго после завершения разбора POST-данных в `sapi_handle_post()`.
3. **Защита от жесткого исчерпания:**
   * При превышении 125% вызывается прямой системный вызов `_exit(1)`, гарантирующий мгновенную остановку процесса ОС без вызова деструкторов.

---

### 4.3. Защита сетевого парсера RFC 1867 (`main/rfc1867.c`)

1. **Строгая фильтрация MIME-заголовков:**
   Парсер принимает только заголовки `Content-Disposition` и `Content-Type`. Все нестандартные заголовки отбрасываются до аллокации памяти.
2. **Контроль `post_max_size` в буфере ввода:**
   Прямое отсечение потока данных в `fill_buffer()`.
3. **Безопасное завершение при нехватке памяти:**
   При взводе Soft-OOM парсер выполняет аккуратный выход через метку `oom:`:
   ```c
   oom:
       if (key) {
           efree(key);
       }
       smart_string_free(&buf_value);
       return 0;
   ```
4. **Обнуление хэша загруженных файлов:**
   ```c
   FREE_HASHTABLE(SG(rfc1867_uploaded_files));
   SG(rfc1867_uploaded_files) = NULL;
   ```
